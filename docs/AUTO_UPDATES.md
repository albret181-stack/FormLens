# Бесплатные обновления FormLens

## Решение

Используется открытый Sparkle 2.10.1 и его официальный CLI. Apple Developer Program, платный сертификат и нотарификация не требуются для выбранного канала. Пакеты ZIP и appcast подписываются бесплатным ключом Ed25519. Публичный ключ встраивается в Info.plist; приватный хранится только у владельца и в GitHub Actions Secret. Проверка подписи перед распаковкой и подпись feed обязательны.

Весь код механизма подготовлен, но установка и перезапуск на реальном Mac ещё не проверены. Это не выпущенное автообновление. Без нотарификации Apple macOS может предупреждать о неизвестном разработчике. Не отключать Gatekeeper или другие проверки глобально.

## Один раз настроить ключ

Для этого проекта публичный ключ уже закреплён в `config/update-public-key.txt`. Владелец получает приватную часть отдельным набором настройки. Требуется добавить только GitHub Actions Secret `FORMLENS_UPDATE_PRIVATE_KEY` в Settings → Secrets and variables → Actions.

Приватный ключ нельзя отправлять в чат или коммитить. Сохранить безопасную резервную копию: потеря ключа может потребовать ручного перехода на новый ключ. Не запускать генератор новой пары для существующего канала обновлений.

Для нового независимого проекта генератор `node scripts/generate-update-key.mjs` создаёт бесплатную пару. Публичную часть такого проекта нужно отдельно закрепить в его сборке. Временная переменная `FORMLENS_UPDATE_PUBLIC_KEY` разрешена только как переопределение для изолированных CI-проверок.

## Сценарий пользователя

Колокольчик → скачать внутри FormLens → «Сохранить разбор и перезапустить».

Sparkle CLI сначала запускается с `--defer-install --check-immediately`: проверяет подписанный feed, загружает и проверяет архив, подготавливает установку. Успешное завершение означает готовность к установке. После отдельного нажатия и успешного сохранения разбора CLI запускается без defer, с `--interactive`: при необходимости он может показать системный запрос разрешения заменить приложение. Терминал и браузер не открываются. Загруженный пакет может быть установлен и при обычном выходе.

Источник — только appcast конкретной версии в `albret181-stack/FormLens`. Внешние URL из интерфейса не принимаются. Загрузка и установка не запускаются одновременно. Ошибки подписи/доступа не выдаются за успех. Sparkle отвечает за замену .app и перезапуск; собственный скрипт копирования системных файлов не используется.

Хранилище разборов, origin `http://127.0.0.1:4175`, имя приложения и bundle ID `local.formlens.studio` сохраняются. При ошибке сохранения или активном анализе/переносе команда установки не отправляется.

Первую версию с бесплатным модулем нужно установить вручную один раз. Прежнее приложение не содержит этого механизма.

## Сборка

Release workflow читает публичный ключ из репозитория, приватный — из единственного Secret выше. Проверка macOS использует отдельные одноразовые ключи и не публикует тестовые сборки. `setup-sparkle.mjs` загружает фиксированный официальный архив Sparkle и проверяет закреплённый SHA-256. Дистрибутив копируется целиком для сохранения структуры framework, CLI и лицензий. Итоговое приложение получает локальную ad-hoc подпись — это не Developer ID и не нотарификация.

Создаются:

- `FormLens-X.Y.Z-arm64.dmg` для первой установки.
- `FormLens-X.Y.Z-arm64.zip` для обновления.
- `FormLens-X.Y.Z-arm64-appcast.xml` — подписанный feed конкретной версии.
- `appcast.xml` — та же подписанная лента для latest release.
- `SHA256SUMS.txt`.

Перед публикацией проверяется, что подпись ZIP соответствует именно публичному ключу, встроенному в приложение. CI создаёт черновик, не публикует непроверенный выпуск. Версию package.json/package-lock.json поднять перед новым тегом.

## Обязательная проверка на Mac

1. Собрать два выпуска N/N+1 с одинаковым публичным ключом; проверить загрузку CLI и framework из упакованной .app.
2. На отдельном тестовом канале проверить N → N+1 с реальными GitHub-артефактами, подписью ZIP/feed, заменой приложения и перезапуском.
3. Проверить сохранённый/несохранённый разбор, отказ записи и запрет установки во время анализа/переноса.
4. Проверить неправильную подпись feed/архива, сеть, повторные нажатия и отсутствие прав записи.
5. Проверить обычный выход с подготовленным обновлением, поведение Gatekeeper и чтение прежнего хранилища после перезапуска.

Node-тесты проверяют криптографию, состояния и запуск CLI через mock, но не реальную замену .app.
