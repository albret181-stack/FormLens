# Горизонтальная тяга сидя: черновик протокола разметки

Статус: **черновик для обсуждения с тренером**. Это не медицинский стандарт и не утверждённый список ошибок. До экспертного согласования приложение не должно называть эти наблюдения доказанными техническими ошибками.

Связано с GitHub Issue #2. Область: тяга сидя на блочном тренажёре, одно непрерывное видео, один человек, камера сбоку. Другие хваты, тренажёры и ракурсы требуют отдельного описания.

## Зачем нужен протокол

Алгоритм должен сначала описывать то, что действительно видно в видео, а затем — только после согласования и проверки — решать, соответствует ли наблюдение ошибке. Угол корпуса, локтя или колена сам по себе не доказывает неправильную технику.

Например, «наклон корпуса изменился на 19°» — измерение проекции. Оно не доказывает раскачивание: причиной могут быть допустимый вариант движения, перспектива, смещение камеры или ошибка позового трекера.

## Что размечает эксперт

Для каждого видео:

- версия протокола и идентификатор клипа без имени файла/участника;
- пригодность ракурса: боковой / частично боковой / непригодный;
- видимость человека, плеча, локтя, кисти и таза отдельно по каждому повторению;
- границы повторения и, если их можно определить, фазы: возврат/разгибание руки и тяга/сгибание руки;
- для каждого предполагаемого события: тип-кандидат, начало и конец, сторона, видимые ориентиры, уверенность эксперта;
- решение: **ошибка подтверждена**, **допустимый вариант**, **спорно**, **не видно**, **не относится к этому упражнению**;
- короткое объяснение решения и, при необходимости, отметку второго специалиста.

Границы события задаются по времени исходного видео. Не размечать кадры с пропущенной видимостью так, будто движение между ними известно.

## Кандидаты для согласования

Пока это гипотезы для экспертной разметки, а не активируемые автоматические предупреждения.

| Кандидат | Что можно измерить на боковом видео | Что измерение само по себе не доказывает |
|---|---|---|
| Изменение наклона корпуса | Изменение угла линии плечо–таз в пределах непрерывного повторения | Что движение является раскачиванием или ошибкой |
| Изменение угла локтя | Минимум, максимум и диапазон угла плечо–локоть–кисть в повторении | Что амплитуда недостаточная или избыточная без согласованного стандарта и видимого тренажёра |
| Согласованность корпуса и руки | Временной порядок измеряемых изменений корпуса и угла локтя | Что конкретный порядок неправильный для всех допустимых вариантов тяги |
| Повторяемость движения | Различия измеренных признаков между видимыми повторениями одного непрерывного клипа | Что вариативность означает ошибку, а не усталость, настройку или намеренный вариант |
| Траектория кисти | Перемещение кисти в координатах изображения | Траекторию рукоятки/троса, если снаряд не распознан; причинную нагрузку на суставы |

### Не выводить из боковой 2D-позы

- движение или положение лопатки;
- округление/разгибание поясницы;
- вращение плеча и локтя в глубину;
- положение стоп и контакт с опорой, если они не видны;
- нагрузку, боль, мышечную активацию и риск травмы;
- «идеальную» амплитуду или единственно верный наклон корпуса.

Эти признаки требуют иных ориентиров, ракурсов или измерительных средств. Отсутствующий сустав не восстанавливать догадкой.

## Единицы разметки и разногласия

1. Эксперт размечает сначала ракурс и видимость, не видя автоматических предупреждений.
2. Затем размечает повторы и фазы.
3. Только после этого оценивает события-кандидаты и их допустимость.
4. Второй специалист независимо проверяет все случаи «спорно» и выборку остальных классов.
5. Сохраняются обе исходные разметки; согласованная версия не стирает разногласия.
6. До согласования словаря классов и примеров «ошибка / допустимо / спорно / не видно» конкретный кандидат остаётся исследовательским измерением.

Порог согласия экспертов нужно определить до сбора контрольной выборки. Разногласия по классу и границам времени учитывать отдельно; их нельзя автоматически превращать в отрицательные примеры.

## Формат события для будущего набора данных

Пример схемы, **не реальная разметка**:

```json
{
  "protocol_version": "row-side-draft-1",
  "clip_id": "anonymous-id",
  "rep": 2,
  "phase": "pull",
  "candidate": "trunk-motion",
  "start_s": 4.25,
  "end_s": 4.80,
  "visibility": "observable",
  "expert_label": "disputed",
  "reviewer_count": 2,
  "notes": "Нужна проверка допустимого варианта"
}
```

Не добавлять исходное видео, извлечённые кадры, имена, аккаунты или метаданные, позволяющие установить личность, в публичный репозиторий. Для проверки нужны отдельное разрешение на использование и контролируемое хранение.

## Критерии перехода к реализации правила

Кандидат можно превратить в детектор, когда:

- тренер утвердил определение и примеры всех четырёх исходов;
- указан ракурс и минимально необходимые видимые ориентиры;
- определены правило сопоставления предсказанного события с разметкой и временной допуск;
- порог выбран на тренировочной части, а оценка выполнена на отдельной выборке, разделённой по людям;
- опубликованы precision, recall, ложные события на подход, временная локализация и охват, включая долю отказов;
- при недостаточной наблюдаемости интерфейс сообщает «недостаточно данных», а не показывает зелёный результат.

До этих условий UI может показывать измерение как наблюдение с ограничениями, но не «ошибку техники» и не вероятность ошибки.
