# Инструкции ИИ-разработчику — FormLens

## Продукт
Локальное Electron-приложение для разбора видео упражнения. Поддерживаемый сценарий в исходном README: горизонтальная тяга сидя, камера сбоку. Показывать наблюдаемые моменты, кадры и оговорки — не объявлять технику правильной только по ключевым точкам.

## Карта проекта
- `app/`: пользовательский интерфейс, видео, MediaPipe Pose, логика упражнений, локальное хранение, отчёт;
- `main.cjs`, `server.cjs`, `preload.cjs`, `update-service.cjs`: Electron, локальный сервер и обновления;
- `tests/`: Node test suite; `scripts/`: упаковка;
- `ROADMAP.md`: существующий план, не перезаписывать без необходимости;
- `RELEASE.md`, `RELEASE_NOTES.md`, `THIRD_PARTY.md`: выпуск и лицензии;
- `.github/workflows/checks.yml`: тесты; `release.yml`: сборка по тегу.

## Инварианты
- Обработка видео локально. Не добавлять скрытых сетевых отправок, телеметрии, облачных зависимостей.
- Демо синтетической позы не считать проверкой качества реальных ошибок техники. Отдельно измерять точность на размеченных реальных роликах; при недостаточной наблюдаемости отказываться от вывода.
- Не терять сохранённые проекты и .formlens при обновлениях; не ломать файловую совместимость молча.
- Приложение должно оставаться простым: видео → разбор → таймкоды и кадры, без лишних панелей и фиктивных функций.
- Не менять версии, опубликованные артефакты, зависимости, модель Pose и релизный канал без отдельной задачи и проверок.

## Проверки
- `npm test` — репозиторные тесты; `.github/workflows/checks.yml` запускает их на Linux.
- `npm ci && npm test` — рекомендованная чистая проверка на машине с Node.js.
- Нативные сохранение, импорт, DMG, обновление, производительность и качество техники **нужно проверять отдельно**, один тестовый прогон Node этого не доказывает.
- `release.yml` требует совпадения `vX.Y.Z` с `package.json`. На дату аудита package.json указывает 0.8.0, хотя в GitHub Releases есть 0.10.0; перед следующим выпуском проверить и согласовать версии.

## Процесс
При явном запросе «Используй пайплайн»: `DEVELOPMENT.md`, существующие GitHub Issues, отдельная ветка и PR. Иначе не навязывать полный цикл. Не сливать PR и не выпускать версию без отдельного поручения.
