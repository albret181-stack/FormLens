# Выпуск FormLens

Репозиторий: https://github.com/albret181-stack/FormLens

## Локальная сборка

```sh
npm ci
npm test
npm run package
npm run dist
```

Образ и SHA256SUMS.txt создаются рядом с папкой проекта. DMG содержит FormLens.app и ссылку на Applications. Скрипт пока выполняет только ad-hoc подпись. Не публикуйте сборку как нотарифицированную.

## Новый выпуск

1. Обновить версию в package.json/package-lock.json, текст интерфейса и RELEASE_NOTES.md.
2. Закоммитить и отправить код в main.
3. Создать и отправить тег vX.Y.Z, совпадающий с package.json.
4. GitHub Actions выполняет тесты, сборку и создаёт **черновик** выпуска с DMG и контрольной суммой.
5. Скачать образ, проверить установку и сохранность проектов на отдельном Mac. Затем опубликовать черновик в GitHub Releases. До публикации пользователи его не видят.

Первый выпуск 0.7 собран локально; из-за обрывов загрузки DMG публикация также выполняется через GitHub Actions. Повторная сборка может заменять файлы только в черновике, опубликованные выпуски защищены от замены. Перед публикацией следующего тега проверьте доступность macos-14 runner в своём аккаунте. Расходы Actions определяются условиями GitHub.

## Что делает колокольчик

Только нативная сборка запрашивает публичный GitHub API в основном процессе, без токена: при запуске, каждые 6 часов и по кнопке. Передаются обычные сетевые данные и версия приложения, но не имена файлов, видео, точки или заметки. Повторные запросы ограничены минутным интервалом. Веб-предпросмотр явно сообщает, что обновления доступны в установленном приложении.

Используются только стабильные теги vX.Y.Z; имя установщика строго FormLens-X.Y.Z-arm64.dmg. URL ограничен точным репозиторием и тегом. При новой версии появляется точка у колокольчика. Кнопка открывает официальный DMG в браузере. Перед заменой приложения нужно сохранить разбор и закрыть FormLens. Профиль и origin 127.0.0.1:4175 сохраняются; сквозное обновление двух нативных версий ещё требует проверки.

## Для настоящей автоматической установки

Нужны Apple Developer ID Application, нотарификация, постоянная идентичность подписи и проверенный канал обновлений. Сертификат и пароли не хранить в репозитории. После их настройки подключить Electron autoUpdater или electron-updater, подписанные манифесты и установку только после явного действия пользователя с проверкой несохранённых данных. Проверить обновление N → N+1, сбой сети, неверную подпись и восстановление после ошибки. В 0.7 этого механизма нет; уведомление и ручная установка не называются автоустановкой.

Официальная документация: https://www.electronjs.org/docs/latest/api/auto-updater
